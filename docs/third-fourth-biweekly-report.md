# 第三、四周双周整合报告

项目名称：语义驱动的 PPT 智能图表生成与多模态配图系统  
报告周期：2026 年 4 月 13 日 - 2026 年 4 月 26 日  
项目负责人：阿曼卓勒·阿迪力江

## 1. 本阶段整体进展

第三、四周项目重点从“模块原型开发”推进到“系统集成与可演示化实现”。本阶段团队围绕语义识别、图表生成、配图优化、PPT 写回和部署能力建设，完成了多项关键工作，初步打通了从内容解析、语义理解、图表生成、配图生成到结果预览和部署的主流程。

相较于前两周，本阶段的主要变化有三点：

- 核心模块从单点可运行提升为前后端联通的系统能力；
- 语义识别和配图模块从基础原型进入可优化、可评测、可人工干预的工程化状态；
- 项目开始提前进入部署与演示准备阶段，完成了容器化和部分性能优化工作。

由于 Project Charter 主要给出了 WBS 和总工时预算，没有细化到“第三、四周”的严格周计划，因此本报告主要从“已完成工作与原 WBS 的对应关系”进行对比。

   已完成本地规则识别、Prompt 优化、RAG 增强和千问 API 接入，整体推进较快。

2. **4.4 图表代码生成与渲染模块开发**  
   已实现图表生成主链路，并扩展了多种图表推荐与输出能力。

3. **4.6 配图生成模块开发**  
   已完成配图生成基础能力、多模型切换、CLIP 打分与重生成闭环，阶段进展较明显。

4. **5.1 工作流编排与模块串联**  
   本阶段已基本完成主流程集成，属于提前推进的部分。

5. **5.2 后端服务开发、5.3 前端界面开发、5.4 结果预览与下载功能**  
   已经形成可演示的前后端联通系统，完成度高于“仅完成模块开发”的初级阶段。

6. **7.1 Docker 容器化**  
   容器化部署工作已提前启动并基本完成，进度快于原计划预期。

### 4.2 部分完成但仍需继续推进的内容

1. **4.1 PPT/文本解析模块开发**  
   已具备基础解析和复杂表格支持，但对真实复杂 PPT 的鲁棒性仍需加强。

2. **4.5 配图检索模块开发、4.7 配图重排与筛选模块开发**  
   当前更偏向生成和筛选闭环，互联网检索、多来源重排和更精细筛选能力仍不充分。

3. **5.5 端到端输出功能实现**  
   主流程已经打通，但增强版 PPT 的最终成品质量和完整写回能力仍需继续完善。

### 4.3 相对滞后的内容

1. **2.3 数据库与缓存设计**  
   Project Charter 中提到 MySQL、Redis 支撑，但目前系统仍以本地文件和轻量化流程为主，数据库与缓存尚未真正落地。

2. **3.x 数据与评测资源准备、6.3 大批量端到端评测、6.5 人工评测与结果分析**  
   当前已有小规模案例库和评估逻辑，但距离大批量评测与系统化人工评估仍有差距。

3. **成功标准中的单文件 `.exe` 版本交付**  
   原计划写明需要 WebApp 与 `.exe` 版本，但目前实际推进路线已转向 `Vue + FastAPI + Docker`，更适合演示和服务器部署，`.exe` 版本尚未实现。

### 4.4 计划调整说明

与最初计划相比，项目技术路线出现了合理调整：

- 原计划中的 `Gradio WebApp` 已演进为 `Vue + FastAPI` 前后端分离方案；
- 原计划强调 `.exe` 可执行打包，但当前优先级已转向 Docker 部署和服务器演示；
- 原计划包含 MySQL、Redis 等基础设施，但当前阶段优先保障端到端可运行与展示效果，基础设施暂缓。

这一调整总体是为了优先完成“可展示、可联调、可部署”的核心目标，符合课程项目中期推进的实际需求。

## 5. 当前问题与后续建议

### 当前问题

- 千问语义分析和配图生成的稳定性仍需通过更多真实样本验证；
- 配图模块虽然已具备闭环，但高质量真实生成能力仍有提升空间；
- 数据库、缓存与大批量评测尚未落地，系统工程深度仍可加强；
- 成果写回 PPT 的最终视觉质量和复杂模板兼容性仍需继续优化。

### 后续建议

1. 继续扩大真实 PPT 数据样本，补足复杂场景测试集。
2. 对千问 Prompt 和多模型配图策略进行进一步调优。
3. 完善增强版 PPT 导出与复杂版式兼容。
4. 补充人工评测和批量性能测试，形成更完整的验收依据。
5. 根据最终交付要求，决定是否补做 `.exe` 打包或继续深化 Docker 方案。

## 6. 结论

第三、四周项目总体推进较快，尤其在系统集成、语义识别增强、图表与配图优化、PPT 写回和 Docker 部署方面取得了明显进展。团队已经从“单模块开发”阶段进入“可演示系统构建”阶段。与 Project Charter 对照看，项目在系统集成和部署方面推进速度较快，但在数据库缓存、大规模评测与最终完整交付形态上仍需继续补齐。
